# Diátaxis quickref

| | Tutorial | How-to | Reference | Explanation |
|---|---|---|---|---|
| **Reader** | New user | User with specific task | User with specific need | User with conceptual question |
| **Voice** | Friendly, hand-holding | Direct, terse | Authoritative, neutral | Opinionated, narrative |
| **Goal** | Get to a "working" experience | Show steps for goal X | Look up exact behavior | Build mental model |
| **Promise** | "Follow this and it will work." | "Do this to achieve X." | "Here is exactly what it does." | "Here is why it is this way." |
| **Example length** | Walk-through full example | Snippet per step | Minimal per entry | Diagrams + prose |
| **Don't** | Explain everything | Be theoretical | Tell a story | Be a how-to |

## Smell tests
- Tutorial that lists every flag of a CLI → that's reference; pull it out.
- How-to that begins "First let's understand…" → cut to the steps.
- Reference that uses "we" or asks rhetorical questions → that's explanation; pull it out.
- Explanation with no diagram or analogy → maybe you don't have an explanation yet; write the tutorial instead.

## Page split rule
If your doc page tries to do two of these, split it. Cross-link.
