# README template

```markdown
# <project-name>

<One sentence: what this is. Not "a powerful tool for…" — "An X for Y".>

<Two sentences: category + differentiator. Why someone should pick this over the obvious alternative.>

## Status

<alpha / beta / stable / archived> · <license> · <maintainer or org>

## Install

​```bash
<one or two commands; the simplest path>
​```

## Quick start

​```<lang>
<minimal complete example — copy-pasteable, runs>
​```

## What it does (when more depth helps)

A short list (≤5 bullets) of the main capabilities. Each bullet is one concrete thing it does, not "powerful".

## Documentation

- [Getting started](link) — guided tutorial
- [How-to guides](link) — task-oriented
- [API reference](link) — exhaustive
- [Concepts](link) — model + why

## Contributing

Link to CONTRIBUTING.md. State the contribution acceptance bar.

## License

<License name> — link to file.
```

## Length guidance
- A README that scrolls more than 2 screens is a doc site in disguise. Move depth elsewhere.
- For libraries: stay terse; link out for guides.
- For applications: install + quickstart + screenshot + link to docs is usually enough.
