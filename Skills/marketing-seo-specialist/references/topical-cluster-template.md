# Topical cluster — hub and spoke

## Hub page (1)
- Comprehensive, long-form page on the topic at a category level.
- URL like `/learn/<topic>` or `/<topic>`.
- Title targets the broad term ("Project management").
- Internally links to every spoke.

## Spoke pages (5–15+)
- One sub-topic each, depth on a single query.
- URL like `/learn/<topic>/<subtopic>`.
- Title targets a specific long-tail variant.
- Each spoke links UP to the hub (and sideways to relevant siblings).

## Authority flow
Internal linking concentrates topical authority on the hub, which then ranks for the broad term, while spokes capture long-tail variants.

## How to plan
1. Pick the hub topic — broad enough to support 10+ subtopics, narrow enough to be your wheelhouse.
2. List all the sub-queries (Ahrefs / SEMrush / People Also Ask).
3. Cluster by intent and depth; each cluster = one spoke.
4. Build the hub first; spokes second (so internal links exist as spokes publish).
5. Refresh quarterly — add new spokes for emerging queries; update outdated answers.
